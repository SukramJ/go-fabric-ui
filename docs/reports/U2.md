## Differences from the brief

1. **A Go runtime dependency.** oapi-codegen's generated router binds
   path and query parameters with `github.com/oapi-codegen/runtime`
   (Apache-2.0; it pulls `github.com/apapsch/go-jsonmerge/v2`, MIT). The
   module's Go dependencies were go-fabric and the standard library; the
   guard admits the runtime in `internal/api` only, THIRD-PARTY-NOTICES
   lists both.
2. **Validation is the binding, not the schema.** The generated code
   checks parameter types and decodes the bodies; it does not enforce
   `minimum`/`maximum`/`maxLength` (that needs kin-openapi's request
   validator, a far larger runtime dependency). The handler bodies check
   every bound the contract states.
3. **`x-admin` is a hand-written table** (`controllerAdmin`), because the
   generator carries no operation extensions;
   `TestControllerAdminMatchesTheContract` holds it against the contract.
   The stream's payload type is hand-written too (the stream's schema is
   text, which the generator does not reach).
4. **Port shape.** Beyond concept §C.1: `Capabilities()` (BLE),
   `ControllerNode.Basic()` (BasicInformation from the image),
   `PairOptions` on `CommissionDiscovered`, `Invoke` with a
   `json.RawMessage` payload and a typed `InvokeResult`. `Write` takes a
   JSON value or the typed `[]ACLEntry` / `[]BindingTarget`; the adapter
   encodes the typed lists from the generated definitions.
5. **Contract guard.** The planned operations' 501 placeholders would
   fail the removal test; the guard now exempts the responses (not the
   path or method) of an operation marked `x-status: planned` in the
   previous contract, with a test.
6. **Shared `Problem` schema.** Its `code` enum gains `node_error`; the
   node routes never answer it.
7. **oapi-codegen `v2.8.0`**, not `v2.8.1` (three days old at the pin);
   runtime `v1.7.0` (August).
8. **Family detection.** `/node/status` never answers 404 (it reports
   `enabled: false`), so the shell hides the node family when it is
   disabled and a controller is present; with no controller the disabled
   node page stays, as before.
9. **Stream content.** `commissioning_progress` has the phases started,
   succeeded, failed (the handler publishes them; the facade has no
   commissioning progress hook), and a failure's kind, never its text.
   `update` is published after a consent or a check (the update manager
   has no observer on the facade).

## Decisions made

- Generated code in `internal/api` (its exported names stay out of
  `fabricui`'s API); strict server with the error handlers mapping
  problems.
- Discovery is admin (concept §C.2); targeted reads of at most 32
  concrete paths, not admin (decision 0.4).
- An ACL write drops a subject naming the node itself and an entry left
  without subjects (matterjs-server, as go-fabric-server mirrors).
- `DELETE …/fabrics/{index}` refuses our own fabric (400): that is
  decommissioning.
- The fabric label is set at once and pushed to the nodes in the
  background, as go-fabric-server answers before the push.
- `node_error` (502) carries the node's error text as its detail, unlike
  the other 5xx problems; it names no host path.

## Questions

Owner decisions after the first hand-back: Q1 — the changelog's 0.2.0
Deprecated section announces the removal in v0.2.1; Q2 — accepted,
confined to `internal/api` by the import guard; Q3 — the go-fabric issue
is filed by the coordinator; Q4 — `contract/previous/` is refreshed to
0.2.0 in this pull request (the guard against main's 0.1.3 baseline
passed first, exit 0).

1. **The comma form of `Item.Fields`.** v0.1.3 deprecated it "until
   v0.2.0"; this wave does not remove it (not in the brief).
   Recommendation: remove it in the release after S4 has bumped, with a
   changelog line now.
2. **A runtime dependency for the generated router.** Recommendation:
   accept `oapi-codegen/runtime` (Apache-2.0, small); the alternative is
   oapi-codegen user templates that bind with the standard library, which
   we would then maintain.
3. **Facade gaps for the stream.** go-fabric offers no commissioning
   progress hook and no observer on `softwareupdate.Manager`.
   Recommendation: a go-fabric CK issue for both, then richer
   `commissioning_progress` phases and `update` events without a
   handler-side publish.
4. **`contract/previous/` at the tag.** The brief keeps the 0.1.3
   baseline; docs/contract.md says the release commit copies the
   contract. Recommendation: copy it in the tagging commit after this PR
   merges.
