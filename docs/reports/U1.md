## Differences from the brief

- Handlers live in package `fabricui`, not `fabricui/internal/api`: the
  exported provider types would otherwise be aliases of an internal package.
- `Verdict` is a type alias of `eligibility.Verdict`.
- Route merges from loom: `/matter/share` and `/matter/commissioning/window`
  → `POST /node/pairing/window`; `/matter/setup-payload` → `GET /node/pairing`
  (serves the open fresh window's codes while it is open); `force-sync` →
  `maintenance/reassemble`; `exposable` PUT + bulk → one batch `PUT
  /node/exposure`. Loom's audit recorder has no counterpart; the audit
  tests port to log assertions (passcode never logged).
- `discriminator`/`passcode` are optional in the pairing and window
  answers (facade gap, Questions 2–3); endpoint clusters carry ids only
  (Question 4).
- Status adds `healthy`, `health_note`, `exposure`, `csrf_token`; sessions
  add numeric twins beside `*_hex`.
- Fabric index 255 answers 400 (loom: 500 from the node).
- A wrong method on an API path answers the API 404 problem, not 405.
- `Select` is a native `<select>`: `bits-ui` is not used. DataTable is
  trimmed (no column-filter row, column groups, expansion). No
  `@fontsource/inter`; system font stack.
- `.npmrc` (`legacy-peer-deps=true`) is required: openapi-typescript 7.13.0
  peers TypeScript ^5, the module pins 6.0.3 (loom's choice). The lockfile
  is written by npm 10.9.4 (local npm 9.2.0 fails on npm overrides).
- The npm package ships sources (no `svelte-package` step).
- The e2e test imports `device` and `controller/commissioner` (test-only
  allowlist of the import guard; production code is facade-only).
- No `fuzz-smoke` job: there is no decoder (bodies are `encoding/json`
  with `DisallowUnknownFields` and a 1 MiB bound).
- Skeleton fixes: `CLA.md` and `AI_POLICY.md` named go-ha2fabric; the
  Makefile's skeleton targets (docker, addon, release binaries) are gone.

## Decisions

- Default window: fresh random credentials (`OpenBasicWindow`),
  `Options.ConfiguredWindow` for the configured passcode; `GET /node/pairing`
  serves the fresh window's codes while it is open, forgotten on close
  (route or observed `window_closed`).
- Loom's empty-topology refusal (503, `Retry-After: 30`) kept, with
  `Options.AllowEmptyTopology`.
- Events: when the host's `*Events` is wired into `node.Config.Observers`,
  routes stop publishing fabric/window transitions themselves (no
  duplicates); exposure and endpoint changes are always route-published.
- Problem `type` URIs point at `docs/contract.md#problem-<code>`.
- Tailwind scans with `source(none)` and excludes test files, so a test
  edit never changes the committed bundle.
- Standalone shell always applies the HA skin; the tokens' standalone
  palette stays for library consumers.
- QR: loom's `qrcode` (MIT) renderer, not a second encoder.
- Contract guard flags a newly required field on an existing schema (a
  reviewer accepts the response-side case).

## Left out

- Controller family (U2), loom's frame-shell detection (`lite-shell`),
  audit log, single-item exposure PUT, Playwright e2e, visual regression,
  CodeQL for JavaScript/TypeScript (would add a required check).

## Questions

### go-fabric facade gaps (CK)

1. **Runtime observers.** `node.Observers` exist only in `node.Config`; a
   handler mounted on a running node cannot learn of a commissioning.
   Needed: `func (n *Node) Observe(o Observers) (unsubscribe func())`.
2. **Window discriminator.** `CommissioningWindow().Discriminator()` is 0
   for the node's own and basic windows (it reports enhanced windows only).
   Needed: `func (n *Node) Window() WindowSnapshot` (the snapshot the
   observer gets, readable at any time).
3. **Configured setup payload.** The facade returns the codes but not the
   configured passcode, discriminator, vendor and product id loom's
   setup-payload served. Needed: `func (n *Node) SetupPayload() (SetupPayload, error)`
   with `Discriminator, Passcode, VendorID, ProductID`.
4. **Cluster and device-type names.** `BridgedDevice` has no clusters; the
   handler reads ids through `Added.Spec().Source.MatterClusterServers()`
   (empty for parts and snapshotter endpoints) and has no names or
   revisions. Needed: `BridgedDevice.Clusters []ClusterInfo{ID, Name, Revision}`
   and `BridgedDevice.DeviceTypeRevision`, or `contract.ClusterName`,
   `contract.ClusterRevision`, `contract.DeviceTypeRevision`.
5. **Fresh window credentials.** Loom drew them with `bridge.Random*`
   (below the facade); the module re-implements the setup-PIN rule.
   Needed: `func NewWindowCredentials(timeout time.Duration) (WindowCredentials, error)`
   or an exported `ValidPasscode`.
6. **Read-only session diagnostics and the node clock.** Sessions and
   occupancy are read through the `SessionManager`/`SubscriptionManager`
   aliases (mutating types); idle ages use wall time while the node may run
   on another clock. Wanted: `func (n *Node) SessionDiagnostics() ([]SessionInfo, Occupancy)`
   with per-session subscription counts, or `Node.Clock()`.

### Owner decisions

1. `@lucide/svelte` is ISC (the brief names lucide; the dependency rule
   says MIT/Apache-2.0/BSD). Recommendation: accept ISC as permissive;
   `check-notices.mjs` accepts it.
2. Home Assistant terms: `CLAUDE.md` bans them, the brief mandates the
   `--ha-*` tokens, the HA skin, `ha-bridge.ts` (Ingress path,
   `<home-assistant>` detection) and go-fabric's ecosystem label "Home
   Assistant". Recommendation: record the theme/ecosystem exception in
   `CLAUDE.md`.
3. `.npmrc legacy-peer-deps=true` vs. TypeScript 5.x. Recommendation: keep
   (loom's precedent, build-time only).
4. Fresh credentials as the default window. Recommendation: keep.
5. `contract/previous/` refresh: copied in each release commit.
   Recommendation: keep; add it to the release checklist.
