## Differences from the brief

1. §7 commits 1 and 2 folded (above).
2. Version: `internal/version` and `ui/package.json` stay 0.6.1 and the
   changelog section is `[Unreleased]`, not `[0.7.0]` — on the caller's
   instruction; the contract is 0.7.0 as the brief says.
3. No pull request opened, no push (caller's instruction).
4. The terms e2e runs in `fabricui/gofabric` (the only place a real
   controller commissions through the handler), not in `fabricui`'s
   `make e2e` test.
5. The adapter applies the terms through `editFor` in `CommissionDiscovered`
   too (host `Edit` first, then the terms), instead of setting them before
   `po.Edit`: one order on both paths, the request wins.
6. `progressFor` chains the template's `Progress` before the port's
   instead of replacing it.
7. `docs/contract.md`'s `problem-not_implemented` now names the erase
   route; no code is new.
8. The docs commit also corrects two citations in code comments: the
   brief's `observers.go:127-136` for `OnEvent`'s goroutine is
   `:121-122` and `:291-292` at v0.18.0 (`events.go`), and the
   `UpdateEvent` fields are `observe.go:99-103` (`updates.go`).
9. Two `rangeValCopy` lint findings (`nodeEntry` grew past 128 bytes) fixed
   by indexing in `mountNodes` and `listNodes`.

## Decisions taken

- Re-announce button only for an admin (`csrf_token` or `Status.admin`,
  as `NodeManage`).
- Erase: 503 without a node is checked before 501 without `Erase`.
- `update_version` is omitted for `check_finished` and for a zero target.
- The step event carries no error text (`PairingStep.Err` stays in the
  adapter).

## Open questions

   observing the old node until the page reconnects; the page reloads by
