## Rules for every reviewer

- **Delta first** (decision 66): the files of the delta map's first table
  line by line before the rest of the unit.
- **Not re-reported**: the rows of the five registers (phases 0, 1a, 1b,
  2, 3). Carried and fixed in this phase's fix wave, so not findings: UR-P1-err-33 (controller route
  404), UR-P2-err-37 (refused write vs node failure), decision 30's
  window kind, UR-P2-err-09, UR-P1-api-171, UR-P3-web-191's rest
  (the node stream is not reopened on a token change). A new path or a
  wider reach of a known row is a new finding that names the old ID.
- **Decided shapes** (decisions 1–68) are the target, not a finding.
- **Show it.** A finding of severity low or above on code carries a test
  that fails today, written and run in a scratch worktree
  (`<scratchpad>/p4wt/<unit>`, `git worktree add --detach … 979a67a`),
  never in the review worktree; a docs or citation finding cites both
  sides' lines. Measured (M) and inferred (I) apart.
- **No sub-agents.** Do not spawn agents; the cap is the coordinator's.
- **No edits** in the review worktree, no commit, no push.
- Severity: high (a role gets a secret or an admin action it must not,
  or a host is misled into an unsafe setup), medium (a real defect with
  a precondition), low, note. Contract (decision 13): say yes/no.
- A security finding of high or medium is a **held candidate**: its
  report stays in `held/` until its fix merges; the first line says so.
