## Rules for every reviewer

- **Not re-reported**: anything in `phase-0-register.md`, `phase-1a-register.md`,
  `phase-1b-register.md`, or the held rows. Open rows decided for phase 3
  (decisions 18–20, 25, 28) are known; a reviewer may add a new path or a
  wider reach to one, as a new finding that names the old ID.
- **Exploits as failing tests** (README X1–X4). Each finding of severity
  low or above carries a test that fails today (Go `_test.go`, vitest, or
  Playwright for a browser-only property, decision 10), written and run in
  the unit's own scratch worktree, never in the review worktree. The report
  gives the test's code and its output. Inferred findings say so.
- **Held material.** UR-P0-auth-20, UR-P0-web-21 and UR-P1-adpt-60 are held
  (decisions 18, 25). A finding of the same class as a held row is a
  **held candidate**: it says so on its first line. Reports go to the git-excluded `held/` directory only.
- Severity: high (a role gets a secret or an admin action it must not),
  medium (a real defect with a precondition), low, note.
- Contract (decision 13): every fix that changes `contract/openapi.yaml`,
  a status code, a field or a gate says so; those go to phase 3.

## Report shape

`held/phase-2-<unit>.md`: per finding ID, severity, `file:line`, claim,
measured (M: read or run) or inferred (I), the failing test and its output,
proposed fix, contract yes/no. Then a short "Covered without finding"
list per flow, so the verifier and the register can see what was read.
