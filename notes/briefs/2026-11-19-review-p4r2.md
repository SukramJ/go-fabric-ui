## Rules for every reviewer

- **Delta first**: the delta map's files of the unit line by line, then
  the rest of the unit.
- **Not re-reported**: the rows of the six registers (phases 0, 1a, 1b,
  2, 3, 4 run 1). Carried and fixed in this run's fix wave, so not
  findings: UR-P4-adpt-197, UR-P4-ui-61's other-tab path, UR-P4-ctr-196's
  mapping of a future window kind. A new path or a wider reach of a known
  row is a new finding that names the old ID.
- **Decided shapes** (decisions 1–75) are the target, not a finding.
- **Show it.** A finding of severity low or above on code carries a test
  that fails today, written and run in a scratch worktree
  (`<scratchpad>/p4r2wt/<unit>`, `git worktree add --detach … 792d15b`),
  never in the review worktree; a docs or citation finding cites both
  sides' lines. Measured (M) and inferred (I) apart.
- **No sub-agents.** Do not spawn agents; the cap is the coordinator's.
- **No edits** in the review worktree, no commit, no push.
- **Scope first.** Before reading, list the unit's files; at the end,
  "Covered without finding" names every file read fully and "Not
  covered" every file not read — no silent gaps (run 1's lesson).
- Severity: high (a role gets a secret or an admin action it must not,
  or a host is misled into an unsafe setup), medium (a real defect with
  a precondition), low, note. Contract (decision 13): say yes/no.
- A security finding of high or medium is a **held candidate**: its
  report stays in `held/` until its fix merges; the first line says so,
  and nothing about it goes into a commit message, issue or public file.
