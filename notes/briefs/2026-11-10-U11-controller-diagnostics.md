## Why
Issue #60 (owner, 2026-11-10): the controller family has no Diagnostics tab because go-fabric had no controller diagnostics. go-fabric v0.21.0 (issue 483, `BD-Matter-ControllerDiagnostics`) serves them: `Controller.SessionDiagnostics() diag.SessionDiagnostics` (sessions of every peer + one `diag.PeerInfo` per peer), `Controller.DiagnosticEvents() []diag.Event`, `Controller.OnDiagnosticEvent(fn)`, `Controller.DiagnoseMDNS() []mdns.Finding`. `node`'s types are now aliases of `diag`'s (no source change for the node side). The owner's decision: the full tab now, contract 0.9.0 (new routes = minor), release 0.9.0.

## Decisions (do not reopen)
1. **Contract 0.9.0, additive.** Three routes under the controller family, mirroring the node ones:
   - `GET /controller/diagnostics` → `ControllerDiagnostics`: `as_of`, `occupancy` (the node's `Occupancy` schema), `sessions[]` (the node's `SessionInfo` schema plus the four new optional fields `created_at`, `resumed`, `transport` (`udp|tcp|ble`), `peer_lost`; omit `idle`/`subscriptions` semantics changes — document that the controller reports 0 subscriptions per session), `peers[]` → `ControllerPeer`: `node_id_hex`, `fabric_index`, `registered`, `state` (`ConnectionState` enum of the contract, mapped from go-fabric's String: Connected→connected, Disconnected→disconnected, Reconnecting→reconnecting, WaitingForDeviceDiscovery→waiting_for_discovery; absent when unregistered), `load_error`, `time_offline_ms`, `operational_address`, `operational_host`, `tcp_unsupported`, `reachable`, `discovered_names[]`, `last_check_in_at`, `next_expected_check_in`, `subscription_active`, `session_ids[]`.
   - `GET /controller/mdns` → the node's `MDNSFinding` list shape (same schema; `no_operational_names` is one more code, listed in the description).
   - `GET /controller/events` → `DiagnosticEventList` (same schema; the kinds gain `reachability icd ota camera`, newest first).
   - Stream: `controller_diagnostic_event` on the existing controller stream carrying one `DiagnosticEvent`; the page refetches on a burst as the node page does (`diagnosticEpoch` in `store.svelte.ts`).
   - `ControllerCapabilities.diagnostics` (bool): true when the source serves them; the three routes answer 501 `not_implemented` otherwise (an adapter over an older go-fabric, or a host's own source). Required in 0.9.0 with the fixtures updated.
   - The node family's `SessionInfo` gains the same four optional fields in the schema (zero/absent on the node; the node handler omits them). One schema, both families.
2. **`ControllerSource` gains** `Diagnostics() (ControllerDiagnostics, bool)`, `DiagnoseMDNS() []MDNSFinding`, `DiagnosticEvents() []DiagnosticEvent`, and `OnDiagnosticEvent(fn) (unsubscribe)`; the port types are fabricui's own (as the node side), mapped from `diag`. A source that returns `ok=false` / nil funcs is "not served". The `gofabric` adapter maps one to one; `DiagnoseMDNS` must not be called from a discovery callback (go-fabric's doc) — call it only from the request handler.
3. **UI:** a `diagnostics` tab in `controllerTabs` (en "Diagnostics", de "Diagnose"), route `#/controller/diagnostics`. The page reuses the node page's cards: discovery (findings), sessions (DataTable; columns add transport, created, resumed, peer lost), a new **peers** card (DataTable: node id linking to `#/controller/node/<id>`, state badge, reachable, operational address/host, time offline, check-ins, sessions), events (newest first, kind badge). No compatibility card (node-only). Hidden when `capabilities.diagnostics` is false: show the kit's "not served" empty state instead of a 501 toast.
4. **Fixtures** from the in-memory controller: `controller-diagnostics.200.json` (two peers: the light connected over udp with one session and a resumed flag; the ICD node waiting_for_discovery with a `no_operational_names` finding and an `icd` event), `controller-mdns.200.json`, `controller-events.200.json`, and the capability in `controller-status.200.json`. `contract-check` on both sides.
5. **Release 0.9.0**: `changelog.md` `[0.9.0]` (Added: the tab and the routes; Changed: go-fabric v0.20.0 → v0.21.0 with one line on #488's reconnect fix and one on #483); version files; `contract/previous` = the 0.8.1 contract; `docs/contract.md` a "Controller diagnostics (v0.9.0)" section; `docs/embedding.md` the source methods; CLAUDE.md state sentence and README status.
